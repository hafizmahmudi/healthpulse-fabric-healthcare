# Security and governance

## Synthetic data

All patient-level records in HealthPulse are synthetic, generated by Synthea. No real personally identifiable health information is used. This is what makes it acceptable to show patient-level tables, quarantine rows, and screenshots publicly.

## Access model

Fabric workspace roles separate engineering from consumption.

| Audience | Access | Items |
|---|---|---|
| Data engineers | Workspace Member or Contributor | Bronze and Silver lakehouses, both warehouses, notebooks, pipelines |
| Analysts | Viewer on the workspace, Read on the warehouse SQL endpoint | Gold warehouse, semantic model |
| Business users | Report access through a workspace app or direct share | Report only; the model is reached through the report |

Raw and quarantined data never leave the engineering layer. The semantic model exposes only the Gold schema and the DQ summary tables.

## Row-level security

Planned, not yet implemented, because the facility key on `FactEncounter` is null until the encounter source is enriched. The design is a `FacilityManager` role on the semantic model filtering `DimFacility` by a mapping table of user principal name to FacilityID, which propagates through the single-direction relationships to every fact. An `Executive` role has no filter. Both roles will be defined in the TMDL under `roles/` and tested with the modeling MCP's impersonation option.

## Secrets

No credentials, tokens, connection strings, or tenant secrets are stored in this repository. Fabric items authenticate to each other with the workspace identity. The `.gitignore` excludes key, certificate, and credential file patterns. The exported pipeline definitions reference items by ID only.

## Staging data hygiene

`stg.DimPatient` in the warehouse carries source columns such as SSN, driver licence, and address as text. It is a load-time staging table and should be truncated after each load or restricted to the engineering role. This is listed as a follow-up.

## What would change with real healthcare data

- Sensitivity labels on every item and label inheritance into Power BI exports.
- Column-level security or masking on direct identifiers in Silver, and no staging copies of identifiers.
- Private endpoints and tenant-level restrictions on export and sharing.
- Audit log review and retention policies for every access to patient-level tables.
- A formal data protection impact assessment and a legal basis for processing before any ingestion.
