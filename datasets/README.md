# Datasets

## Synthetic-data statement

All patient-level records in HealthPulse are synthetic. They were generated by [Synthea](https://synthetichealth.github.io/synthea/), an open-source synthetic patient generator, and redistributed as public datasets on Hugging Face. No real personally identifiable health information is used anywhere in this project. The repository itself contains no data files; see `.gitignore`.

Downloads:

- SyntheticMass clinical ZIP: `huggingface.co/datasets/ajitonelson/synthetic-mass-health-data` (file `SyntheticMass_Data_Hack_ArangoDB.zip`)

Volume after loading: about 1.59 million patients, 15.1 million encounters, 62.7 million observations. This is well above the plan's initial 10,000 patients and is what the optimization and data quality numbers in this repository were measured on.

## Reproduction

1. Run `notebooks/bronze/HP_05_01_NB_SourceIngestion.ipynb` once against the Bronze lakehouse. It downloads every file above into `Files/synthea/raw`, extracts and converts to CSV under `Files/synthea/extracted/clinical` and `.../external`, and stamps `_ingestion_timestamp` and `_source_system`.
2. Insert the thirteen rows into `metadata.SourceConfig` (see `pipelines/README.md`). Paths are relative to the lakehouse `Files/` root.
3. Run `HP_04_PL_Health_Master`. Every active source is loaded into its Bronze table and logged.

## Known data characteristics

- The Synthea encounter extract in this dataset carries only ID, date, patient, code, description, reason code, and reason description. There is no encounter class, start or end time, cost, organization, provider, or payer. Downstream columns designed for those attributes are null until a richer extract is loaded.
- Encounter dates run from 1911 to 2017-05-28. 2016 is the last complete year and is the report's default.
- Race contains a few malformed values (`M`, `S`, `irish`) that the Silver rules do not currently reject.
